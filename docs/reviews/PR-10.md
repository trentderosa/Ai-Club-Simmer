## Correctness: no blocking issues found
- The timeout covers both the request and the body read (one `AbortController` passed to `fetch`), and the timer is always cleared in `finally`.
- `already_awarded` is only reported for a 409 whose body has code `23505`, so other 409s aren't silently swallowed by reconcile.

## Non-blocking notes
1. **Order inversion on retries.** Suppose check-in A on slot 1 fails its live award, and a later check-in B on slot 1 then succeeds live. B is recorded as the first completion, and reconcile later awards A as a repeat at 50%. The total XP is the same, but `is_first_completion` lands on the later check-in. This is fine for the demo, and it's noted in the PRD next to open question 10.
2. **Lookback cliff.** Check-ins older than `XP_RECONCILE_LOOKBACK_HOURS` (7 days by default) are never retried. Since nothing schedules the job, run it at least weekly, and before the demo (it's in `docs/DEMO_SETUP.md`).
3. **CI path filter.** `db-tests.yml` should also trigger on `ai-server/src/jobs/reconcile-xp-core.ts` and `ai-server/src/services/xp-awarder.ts`. This is fixed on `claude/eloquent-dijkstra-x1qp33`, which builds on this PR.
